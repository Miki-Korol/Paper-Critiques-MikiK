# Analyzing Modern NVIDIA GPU Cores

**Paper:** Rodrigo Huerta, Mojtaba Abaie Shoushtary, José-Lorenzo Cruz, Antonio González · *arXiv 2025* · [Link](https://arxiv.org/abs/2503.20481)  
**Critique by:** Miki Korol · 11/01/26  
*Written for CS 254A: Advanced GPU Microarchitecture, UCLA*

---

This paper aims to highlight and model the novel techniques used in modern GPUs. Commonly used models in GPU research are models developed for architectures from 2006\. Specifically they are modeled after the NVIDIA Tesla architecture. Because of the rapidly evolving architecture of modern GPU’s the author claims that we have to update these models to be able to conduct more effective and useful research. The problem is that these GPU architectures are proprietary so modeling the architecture directly is not exactly possible. There is one figure showing that on some workloads, accel-sim, a standard gpu simulator, has an absolute error prediction of 500% while the methods in the paper never get an error higher than 63%.

The author works around the lack of knowledge on the specific implementations by using targeted reverse engineering techniques to uncover the implementation of several components of modern NVIDIA GPUs. The authors use microbenches targeted at specific control bits or microarchitectures and wrap it in instructions that save the clock counter so they could compare the execution time and cycles on slight changes to the benchmark.

The method they use differs for the microarchitecture that they are targeting but generally consists of executing a list of targeted instructions aimed at uncovering the bounds of the microarchitecture for example to uncover the register file methodologies they filled the register file in different ways tracked how the instruction would stall if the value was stored in the same register bank but they noticed that if two fixed length instructions finish at the same time neither stalls so it must mean there is a queue. More methods like this help them uncover more like the fixed operand cycles to 3 hinting towards no operand collector and more.

The most important discoveries they made about the microarchitecture are the removal of hardware dependency checks and moving to a software dependency handling. They also found that for the instruction to be issued there needs to be confirmation first that it can read the operands within the next three cycle window. This is so that once issued the instruction takes a fixed latency and then dependent instructions know exactly when to be issued. They found out that the register file is split into only 2 banks each with one read write port the size of one warp assigned register file. They found out that fixed latency and variable latency ints check separate caches which they call L0 fixed latency and L0 variable latency. And more\! Using this information they made edits to the existing model like changing the L2 cache to be bigger and accommodate the calls with an altered hash, added instruction cache and stream buffer, overhauled the issuer to follow the software defined greedy then youngest they uncovered, removed the operand collector and made the bank operand 3 cycle deterministic check, new instructions from modern GPUs, control bit access and more.

They show consistent improvement in mean absolute percent error (MAPE) across many tests against several gpu generations. They also showed good accuracy on i cache prefetch modeling keeping the MAPE below 35 % on prefetch configurations.

This paper rigorously tested different microbenches to uncover novel adjustments in modern GPU’s Its strengths are the rigor and detail with which the microbenches testing specific register configurations and instruction counts to test the edges of the microarchitecture and get specific hardware insight. It highlights the field's reliance on an unreliable model and uniquely probes real GPU’s to update the assumptions offering a new model which was proven to more closely resemble modern GPU architecture.

One issue in the paper is the over reliance on MAPE in qualifying the results as good/bad. They share the MAPE for all measurements which is not fully representative of the consistency between the model and the GPU because they do not know the buffer sizes and they state in the paper that they could not find the correct read policy that matches for all the benchmarks stating that it may be highly dependent on the instruction count or other instruction factors. Because of the assumptions made we are not fully sure that the low error comes from assumptions or better matches to the underlying architecture.
